# 编码缺失下的多数识别与完整来源敏感性

2026-09-08。此修订在原三轮及 research/85 的两次诊断请求全部结束后形成。两份 DeepSeek 请求持续被提供方以 `SensitiveContentDetected` 拒绝；不改写输入、不换通道、不再追加请求。原完整三编码覆盖门槛没有通过：有效编码仍为 10,750 / 10,752。

检查两条受影响回答的其余编码后，发现每条回答的全部八事件均有两个相同的已观察标签。本修订在知道这一一致性后制定，不是事先规定的缺失数据规则。未按标签正负选择回答、评审、重试或研究终点。

对于某个事件的 n 个有效二元编码与正票数 s，未知票数为 3−n。三票多数的下界为 `int(s >= 2)`，上界为 `int(s + 3 - n >= 2)`。上下界相等才保留为已识别多数；不同则停止该完整面板分析，不将缺失填为 0、1 或其他评审标签。本次两个已知标签相等，因此 16 个事件的多数均唯一确定。第三位编码者的原始标签仍缺失，三人全体一致性保持未知。

在单独的 `analysis_identified` 目录，沿用冻结分析的来源划分规则、Jeffreys 平滑、Brier 比较和固定预测来源 bootstrap，计算完整 256 来源、3,584 回答、三核心事件的多数结果。它是完成多数识别后的分析，不伪装成通过原 10,752 份完整编码门槛。原失败运行和不完整诊断目录保留。

额外报告两种敏感性：

- 去掉受影响的两个完整来源（全部模型与指令），在共同 254 来源上分别为三位编码者及多数标签重新交叉拟合。五折按相同固定哈希排序规则在 254 来源重新分配；与原 256 来源的折成员并不完全相同。每个编码者在这个面板均无缺失。
- 完整 256 来源上逐一删除生成模型，只评价原多数预测的剩余模型损失，不重拟合，延续原方案的这种敏感性。

这些敏感性以及多数识别属于透明的事后修订，不增加确认性 p 值，也不把条件 bootstrap 当作包含全部拟合依赖的不确定性。对原三人多数终点的未知票范围由上述穷尽二元取值的上下界处理，不把高评审一致率说成语义真值。

无论结果方向如何，公开全部三事件、两指令和七配置的冻结比较，并披露缺失比例、提供方拒绝、两次额外诊断尝试和完整来源敏感性。没有人工标注、没有补写缺失编码、没有新导师生成。此分析是否完成与最终论文的质量判断继续分开。
