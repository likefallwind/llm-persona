# 档案自然对话输入恢复：可以使用什么证据

日期：2026-09-07。此轮完全离线，无 API 调用，无新增人工标注。它推进自然回答验证的输入准备，尚未产生新的行为编码或模型人格结论。

## 已完成的恢复

从当前 EduBenchmark 适配器读取真实的源数据，执行 `load_items()` 与 `build_messages()`，恢复 MRBench tutor、BEA tutor、MathTutorBench scaffolding/pedagogy 及其 hard 两臂，共六任务、3,454 个任务条目。对冻结 census 中对应的 92 个预测文件及其 summary 逐一核验 SHA-256，全部一致；54,264 个文件级最新成功项目全部找到当前条目，零未匹配。

保留输入变体、模型、条目和回答文本差异后得到 46,356 条索引；忽略输入变体的文本盘点为 30,086 条，不能将这个缩减口径冒充同请求去重。standard 变体有 24,178 条：M3、M2.7、GLM-5.2、DeepSeek-v4-pro、Doubao-2.0-pro、Qwen3.5-4B、Qwen3.8-27B 各 3,454 条。每个 standard 模型—条目格内恰有一个不同回答文本；跨目录的同文本保留所有文件与行号指针，不计作新的重复试验。

## 恢复到哪一层，仍缺哪一层

当前输入 messages、原始对话、明确题干、参考解和它们的哈希均已保存到本地。131 个 MR/BEA 条目没有可机械分离的首轮题干；MathTutorBench 四臂合计有 420 个空 `problem` 字段。合计 551 个条目、250 个归组仍无单独恢复的问题。部分对话里包含可解的局部问题，但本轮没有把自动猜测当作恢复事实；其余 710 个归组至少有明确恢复的问题。

参考解也不能只检查非空：475 个条目实际上是 `N/A` 或 `Not Available` 占位符，300 个 BEA 条目没有参考解，2,679 个有非占位参考文本，后者仍未经本研究验证。脚本明确区分三种状态。没有将既有人类教学质量标签或导师 gold 回答当作新的人格编码真值，也没有输出隐藏推理。

对 Git 历史进一步比较命名方法的语法树：MRBench 与 BEA 的 `load_items` 在各六个历史快照中一致，MathTutorBench 共用方法在四个快照中一致，默认 `build_messages` 在八个快照中一致。这使“当前恢复路径完全凭空猜测”的疑虑减轻，但只核验了这些方法本身；它没有证明运行时使用的全部常量、辅助函数、数据版本、客户端变换和远端参数相同。

因此，证据等级仍是 **当前适配器输入重建 + 已冻结回答文件的精确定位**，不能写成“逐请求保存的历史输入已全部找回”。历史记录仍缺返回模型权重身份证据；尤其不能把 GLM-5.2 视为当前 GLM-5.3，把历史 Doubao-pro 替换为当前 lite。

## 下一步自然回答验证的边界

这六任务都有教学策略要求，包含禁止直接给最终答案、最多两句、定位错误等条件。它们适合检验既有行为画像在更自然的对话、明确教学指令下何时保持、何时改变，不能直接当作不受指令约束的默认人格测试。MathTutorBench 标准与 hard、大量跨任务条目共享来源；所有后续划分和不确定性分析必须沿此来源图进行，不能按回答行随机分 train/test。

后续先冻结目标问题足够清晰、模型交集明确的来源面板，保留完整纳入/排除索引。对缺失目标的问题，不应直接给出 answer_reveal=0；需要先恢复具体目标，或将该事件标记为暂不可判。情绪/困难承认和推理邀请也需要真实上下文的编码有效性检查，不能把“带问号”当作 reasoning_elicitation。

这些档案已用于探索，后续新编码仍是档案外部检验，不能宣传成从未接触过的原始确认集。与 v3/v4 的共同部署、不同部署和强指令分别报告；如果迁移失败，失败本身应限制论文的人格表述。

`artifacts/educational_personality_v4/archive_bridge/` 保存 summary、材料哈希索引、回答文件/行号索引、来源合并边及方法历史比较。原始对话和恢复的完整请求只存于已忽略的 `local/materials.jsonl`，没有发送到外部服务，也未加入版本控制。

跨措辞实验的后台启动仍因自动审批要求明确的新载荷外发授权而未执行；本审计没有尝试绕过该限制。论文质量目标继续开放，输入恢复完成不等于自然对话行为验证完成。
