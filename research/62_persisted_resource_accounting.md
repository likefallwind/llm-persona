# 已保存调用的资源核算

2026-09-05。用于最终论文的资源披露；当前确认编码仍在运行，所有汇总均为可刷新的中途快照。

`scripts/summarize_personality_resources_v3.py` 汇总 `artifacts/educational_personality_v2/` 下的实际 `responses.jsonl`，分开材料检查、测量开发、训练生成／编码、确认生成／编码及运行诊断。不会把失败量表开发或连通测试合并进正式人格样本数。

## 防止重复与遗漏的规则

1. 以 provider、endpoint、请求模型、request_id、payload 哈希与 started_at 定位一份原始保存记录。同一原始记录被复制到修复目录时只计一次；同一题重新调用但 started_at 不同则另外计数。
2. 身份相同但内容或尝试记录不同的副本导致核算失败，不任意选较大或较小用量。每份记录的尝试序号必须连续且无重复。
3. 优先逐尝试加总 token；顶层最后一次用量不再重复加总。早期只有一次成功尝试且尝试内没有 usage 字段时，可以使用该记录的顶层 usage，并单独记录兼容计数。多次尝试不通过顶层用量猜测分次成本。
4. 缺失用量另计未知次数，不解释为零成本。reasoning token 通常已属于 completion token，不额外相加；各服务的计量与计费口径仍可能不同。
5. 对正在追加的文件只读取完整 JSONL 行的字节前缀，保存前缀长度和 SHA256。文件依次读取，快照不是跨文件同一时刻的事务。
6. 中断或在途请求若没有保存输出，无法在此核算。报告是已保存记录的服务端用量，不是账单核销或完整墙钟时间。

## 当前核验与产物

五项定向测试通过：缓存复制去重、两次 HTTP 尝试分别计入、新执行不误判为缓存、冲突副本拒绝、缺失用量保留及旧单次成功记录兼容，其中缓存测试同时覆盖多次尝试。

当前数据中识别出 7,607 份复用副本；先前若直接对全部响应文件求和，会把这些记录重复计入。475 份早期单次成功记录可以从顶层恢复用量。41 次已保存尝试仍缺少 token 信息；这些是本轮快照的实际缺口，运行后续可能新增。

输出位于 `artifacts/educational_personality_v2/resource_accounting/`：

- `summary.json`：快照时间、去重前后记录数、尝试数、已知 token 与未知用量次数。
- `unique_saved_records.csv`：原始身份哈希、文件／行定位、阶段、请求配置、真实预算和逐记录用量；无回答正文或凭据。
- `reported_usage_by_phase.csv`：阶段、服务、请求模型与预算分组。
- `input_prefixes.json`：所有输入文件的读取长度、完整行前缀哈希与忽略的尾部字节数。

最终实验结束后须刷新此汇总并复核原始前缀。资源核算中的模型名是请求配置；实际返回部署身份以生成与编码审计为准。不用中途 token 总数估计整项研究完成程度，也不把记录数当作独立情境数。
